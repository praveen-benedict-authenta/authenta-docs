# Installation Setup

This guide will walk you through the process of installing Authenta On-Prem in your environment.

## Prerequisites Check

Before proceeding, ensure you have met all [prerequisites](/on-prem/prerequisites):

- Hardware requirements
- Software dependencies
- Network access
- Storage setup
- Authenta Registry Credentials

## Installation Steps

### 1. Configure AWS Credentials

```bash
# Configure AWS CLI for ECR access
aws configure set aws_access_key_id <AWS_ACCESS_KEY>
aws configure set aws_secret_access_key <AWS_SECRET_ACCESS_KEY>
aws configure set default.region us-east-1
```

> Tip: Replace \<AWS_ACCESS_KEY\> and \<AWS_SECRET_ACCESS_KEY\> with the value provided by Authenta Support.

> Note: Authenta provides its AWS Account ID and **read-only ECR credentials** privately to verified enterprise clients during onboarding. These credentials are required to pull container images from Authenta's private registry. For credential delivery or renewal, please contact [Authenta Support](/on-prem/support).

#### ✅ Verify AWS Login

You can verify that your AWS CLI is configured correctly and authenticated by running:

```bash
aws sts get-caller-identity
```

Expected output:

```json
{
  "UserId": "AIDAEXAMPLE123",
  "Account": "111122223333",
  "Arn": "arn:aws:iam::111122223333:user/authenta-client"
}
```

If this command returns valid account information, your AWS credentials are correctly set up.

### 2. Download Authenta Deployment Artifacts

Clone the on-prem deployment repository:

```bash
git clone https://github.com/phospheneai/authenta-on-prem.git
cd authenta-on-prem
```

This folder contains:

- `docker-compose.yml` — defines the required Authenta services (`postgres`, `api-server`, `ml-task-runner-gpu`)
- `setup.sh` — logs in to Authenta's private ECR and pulls the current images
- `shared/` — host directory mounted into `ml-task-runner-gpu` for local input/output file exchange

---

### 3. Authenticate and Pull Images

```bash
sh setup.sh
```

This logs in to Authenta's private ECR (using the AWS credentials configured in step 1) and pulls the images referenced in `docker-compose.yml`.

---

### 4. Start the Stack

```bash
docker compose up -d
```

> Once the containers are up, `postgres`, `api-server`, and `ml-task-runner-gpu` will start automatically. `ml-task-runner-gpu` registers itself with `api-server` on boot and begins polling for jobs.

---

### 5. Apply Database Migrations (first run only)

The container images don't run migrations automatically. From the `authenta-api-server` source checkout, point Drizzle at the exposed Postgres port and run:

```bash
DATABASE_URL=postgres://authenta:authenta_dev_password@localhost:5432/authenta bun run db:migrate
```

---

### 6. Verify Deployment

Check the running containers:

```bash
docker compose ps
```

You should see containers for:

- `postgres`
- `api-server`
- `ml-task-runner-gpu`

Check that the API server is healthy and the worker registered successfully:

```bash
curl http://localhost:8080/api/v1/health
docker compose logs -f ml-task-runner-gpu
```

Once these are active, Authenta On-Prem is deployed and ready to process inference jobs.

> ✅ **At this stage, your service is live.**
> You can begin creating jobs through the Authenta API Server — the ML Task Runner will automatically pick them up and process them with the configured models.

---

## Post-Installation

1. Change the default credentials before any use beyond local testing — at minimum `POSTGRES_PASSWORD`, `AUTH_JWT_SECRET`, `CRYPTO_ENCRYPTION_KEY`, and `WORKER_BOOTSTRAP_TOKEN` in `docker-compose.yml` (see [Configuration](/on-prem/configuration)).
2. Once verified, you can **disable internet access** for full offline operation.
   Authenta continues to function without any external connectivity.
