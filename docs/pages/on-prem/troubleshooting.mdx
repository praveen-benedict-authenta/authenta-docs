# Troubleshooting

## Overview

This page provides solutions to the most common issues you may encounter while deploying or operating **Authenta On-Prem**.
It covers installation, container runtime, database, API server, worker registration, GPU setup, and update-related problems.

All issues can be diagnosed locally — no external internet or cloud dependencies are required.

## 1. Quick Diagnostic Checklist

Before diving into specific problems, verify the following:

| Check                    | Command                                             | Expected Output                                |
| --------------------------- | ------------------------------------------------------ | -------------------------------------------------- |
| Docker running             | `systemctl status docker`                             | Status: **active (running)**                     |
| Containers active           | `docker compose ps`                                    | `postgres`, `api-server`, `ml-task-runner-gpu` all `Up` |
| Disk space                 | `df -h`                                                | Sufficient free space (≥20 GB)                    |
| Shared volume exists        | `ls ./shared`                                           | Directory accessible                              |
| API server healthy          | `curl http://localhost:8080/api/v1/health/ready`       | `200 OK`                                          |
| Worker registered           | `docker compose logs ml-task-runner-gpu \| grep "Worker registered"` | Log line present                        |

If all checks pass but the issue persists, refer to the sections below.

## 2. Docker & Container Issues

### 🐳 Containers Not Starting

**Symptom:**

```bash
docker compose up -d
# -> error: service failed to start
```

**Possible Causes:**

- Invalid Docker Compose syntax
- Missing shared volume directories
- Port conflicts with other services (`5432`, `8080`)

**Resolution:**

1. Validate compose syntax:

```bash
docker compose config
```

2. Ensure directories exist:

```bash
mkdir -p ./shared ./demo-app/data
```

3. Check port usage:

```bash
sudo lsof -i :5432
sudo lsof -i :8080
```

### ⚙️ Containers Exit Immediately

**Symptom:**

```bash
docker compose ps -a
# shows api-server or ml-task-runner-gpu exited
```

**Resolution:**
View logs for details:

```bash
docker compose logs api-server
docker compose logs ml-task-runner-gpu
```

Common causes:

- `api-server` missing a required production secret (`AUTH_JWT_SECRET`, `CRYPTO_ENCRYPTION_KEY`, `DATABASE_URL`, `WORKER_BOOTSTRAP_TOKEN`, `DOMAIN`) — it exits on boot if any of these aren't set
- `ml-task-runner-gpu` has no valid listener configured — it requires `AUTHENTA_API_URL` (or `FILE_TASK_DIR`/`RABBITMQ_URL`/`SQS_QUEUE_URL`) to be set, otherwise it exits with `No listener configured`
- Corrupted Docker image

Try:

```bash
docker compose down
docker compose pull
docker compose up -d
```

## 3. Database & API Server Issues

### 🐘 API Server Can't Reach Postgres

**Symptom:**
`api-server` logs show connection errors, or `curl http://localhost:8080/api/v1/health/ready` returns non-200.

**Possible Causes:**

- `postgres` container not healthy yet when `api-server` started
- `DATABASE_URL` doesn't match `postgres`'s configured user/password/db

**Resolution:**

1. Verify Postgres is accepting connections:

```bash
docker compose exec postgres pg_isready -U authenta
```

2. Confirm `DATABASE_URL` on `api-server` matches `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` on `postgres` in `docker-compose.yml`

3. Restart in dependency order:

```bash
docker compose up -d postgres
docker compose up -d api-server
```

### 🔑 `api-server` Exits with "Environment Variable ... not set"

**Symptom:**
`api-server` logs a config error and exits immediately.

**Resolution:**
The API server runs with `NODE_ENV=production`, which requires several secrets to be set explicitly (no fallback to defaults): `DOMAIN`, `DATABASE_URL`, `AUTH_JWT_SECRET`, `WORKER_BOOTSTRAP_TOKEN`, `CRYPTO_ENCRYPTION_KEY`. Check the error message for the specific key and set it in `docker-compose.yml` under `api-server`'s `environment:` block — see [Configuration](/on-prem/configuration).

## 4. Worker Registration Issues

### 🚫 Worker Not Registering

**Symptom:**
`docker compose logs ml-task-runner-gpu` never shows `Worker registered`, or shows `Worker registration failed`.

**Possible Causes:**

- `WORKER_BOOTSTRAP_TOKEN` doesn't match between `api-server` and `ml-task-runner-gpu`
- `AUTHENTA_API_URL` unreachable (`api-server` not up yet, or wrong hostname)
- `AUTHENTA_API_URL` not set at all — the worker silently falls back to looking for `RABBITMQ_URL`/`SQS_QUEUE_URL`, and exits with `No listener configured` if none are set

**Resolution:**

1. Confirm both services reference the same bootstrap token in `docker-compose.yml`
2. Confirm `api-server` is reachable from the worker container:

```bash
docker compose exec ml-task-runner-gpu curl -i http://api-server:8080/api/v1/health
```

3. Restart the worker after fixing config:

```bash
docker compose restart ml-task-runner-gpu
```

### 📭 Jobs Not Processed / Stuck in `queued`

**Symptom:**
Jobs created via the API never leave `queued`.

**Resolution:**

1. Confirm at least one worker is registered and not stale:

```bash
curl http://localhost:8080/api/v1/workers -H "Authorization: Bearer <operator-token>"
```

2. Check the worker's poll loop is running (should log a lease attempt roughly every `WORKER_POLL_INTERVAL` seconds)
3. Restart if needed:

```bash
docker compose restart ml-task-runner-gpu
```

## 5. ML Task Runner & Model Issues

### 🧠 Model Not Loading

**Symptom:**
Logs show an error resolving a task type's model directory.

**Resolution:**

1. Confirm the task type's slug is included in `WORKER_CAPABILITIES`
2. Re-pull the image and restart:

```bash
docker compose pull ml-task-runner-gpu
docker compose up -d ml-task-runner-gpu
```

### ⚡ GPU Not Detected

**Symptom:**
Logs show:

```json
{ "level": "warn", "msg": "No GPU available" }
```

**Possible Causes:**

- Missing NVIDIA drivers
- NVIDIA Container Toolkit not installed
- Docker daemon not restarted after installation

**Resolution:**

1. Verify drivers:

```bash
nvidia-smi
```

2. Install toolkit:

```bash
sudo apt-get install -y nvidia-container-toolkit
sudo systemctl restart docker
```

3. Test GPU:

```bash
docker run --rm --gpus all nvidia/cuda:12.0-base nvidia-smi
```

4. Restart Authenta:

```bash
docker compose down && docker compose up -d
```

## 6. Performance & Scaling Issues

### 🐢 Inference Too Slow

**Possible Causes:**

- GPU not actually being used (falling back to CPU)
- Insufficient memory
- Heavy concurrent load with only one worker instance

**Fix:**

1. Confirm GPU is in use (see previous section)
2. Increase task runners — remember each replica needs a unique `WORKER_INSTANCE_ID` (see [scaling caveat](/on-prem/architecture#scalability)):

```bash
docker compose up -d --scale ml-task-runner-gpu=3
```

3. Monitor resources:

```bash
docker stats
```

## 7. Logs & Debugging Commands

Useful commands for investigating issues:

| Purpose                | Command                                          |
| ------------------------- | ---------------------------------------------------- |
| View all containers      | `docker compose ps`                                  |
| View API server logs      | `docker compose logs api-server`                     |
| View ML runner logs       | `docker compose logs ml-task-runner-gpu`             |
| View Postgres logs        | `docker compose logs postgres`                       |
| Inspect container          | `docker inspect <container_name>`                    |
| Check Docker network       | `docker network ls`                                  |
| Enter container shell      | `docker compose exec ml-task-runner-gpu /bin/bash`   |
| Validate compose           | `docker compose config`                              |
| Restart all services       | `docker compose restart`                             |

## 8. Contacting Support

If your issue persists:

1. Collect logs:

```bash
docker compose logs > authenta_support_logs.txt
```

2. Include:

   - OS version
   - Docker and Compose versions
   - Short issue description

3. Send to: support@authenta.ai

## Summary

| Issue Category            | Typical Cause                              | Resolution                              |
| --------------------------- | ---------------------------------------------- | -------------------------------------------- |
| Containers not starting     | Missing volumes / ports in use                 | Validate compose config                     |
| `api-server` exits on boot  | Missing production-required secret              | Set the secret named in the error message   |
| Worker never registers      | `WORKER_BOOTSTRAP_TOKEN` mismatch or unreachable API | Align tokens, check network              |
| Jobs stuck in `queued`      | No healthy registered worker                   | Check `/api/v1/workers`, restart worker      |
| No result output            | Wrong volume/`FILE_URI_PREFIX` mapping         | Fix path + permissions                       |
| GPU not detected            | Missing toolkit or driver                       | Reinstall and restart                        |
| ECR auth fails               | Expired credentials                             | Re-login and retry                           |
| Slow performance             | GPU not in use or too few workers               | Verify GPU, scale containers                 |
